#! nostage
# Varda - a dungeon pins itself when you go in, and only when you go IN.
#
# This is the feature the mod is named for, and until now it was a thing to walk into by hand.
# It is reachable after all: ZoneSystem.TestSpawnLocation puts a real crypt in front of you,
# and Teleport.Interact IS entering one - the component's own OnTriggerEnter calls it when you
# walk into the doorway and the use key calls it when you press E, so there is no third path
# this could be imitating.
#
# Run it in SINGLEPLAYER. Placing a location is the host's to do; on a client the vanilla call
# returns false and says nothing about why.
#
# Stand somewhere with no pins of your own within 60 metres. The first line asserts that.
#
# The crypt is placed with disableSave, so it is gone on the next load and no world is left
# carrying a burial chamber somebody put there to check a pin. The PIN is saved, though, and
# that is the point of it - clear it by hand afterwards if you care.
#
# NO STAGE. The `#! nostage` line at the top turns off the ground Devkit makes ready before the
# first step, because the crypt wants the world's own ground under it. A location levels its own
# pad with the game's older terrain system, and the game applies that before the terrain compiler
# a stage writes to, so on staged ground the stage's change is added on top of the pad, and the
# crypt's doorway can end up under the ground or above it. A suite run still starts this file on
# ground the files before it staged, since nothing here moves you first, the way it used to start
# on their `flatten`, so run it from somewhere nothing has levelled when the crypt's ground matters.

clear
god
ghost

# A known map, the way `wipe` gives a known patch of ground. It DELETES saved pins within 60m,
# including ones you placed by hand, which is the same bargain wipe makes with buildings.
unpin 60
pins 0 60

# Crypt2 is a Black Forest burial chamber. Any dungeon location works here; what matters is
# that it has a Teleport pair, which every one of them does.
location Crypt2
wait 3

# Walking past the door does nothing. That is the whole design rule - the pin is a record of
# where you have been, never a hint about where something is - so it is worth one line to
# prove the mod is not simply pinning whatever is nearby.
pins 0 60

enter

# Not a wait. TeleportTo raises a flag and UpdateTeleport carries the move out over later
# frames once the destination has streamed in, and while that flag is up every further
# TeleportTo returns false. Two seconds was not enough, three was not enough and six was,
# which is a fact about how long a crypt took to load that afternoon rather than about the
# game. `landed` reads the flag.
landed

# Pinned.
pins 1 60

# No label under the pin, because NameDungeons is off by default - the icon says what the
# thing is and a name under it repeats that in words on a map whose job is to be glanceable.
#
# Asserting the ABSENCE is worth a line: the name still has to be computed to be suppressed,
# and the way this breaks is the setting being ignored rather than the pin going missing. The
# run before this one proved the other half - with it on, the pin read "Burial Chambers",
# taken from the entrance's own m_enterText.
pinned Burial no

# Going back out and in again does not stack a second pin. The merge check is what stops it,
# and it is the same one that leaves a pin you placed by hand alone.
#
# `landed` between, for the reason above: a second entry while the first is still landing is
# refused by the game rather than by the mod, and this would fail for a reason that has
# nothing to do with what it is testing.
enter
landed
enter
landed

pins 1 60

# Back out, so this file hands the world over the way it found it. Without it the scenario
# ends with the player three kilometres up inside the crypt, and the NEXT scenario opens
# there: that is how the portal one came to place both its portals at y 5042, on top of each
# other, and count one pin where it wanted two.
enter
landed

# A line after `landed`, for a Devkit older than 1b48353. `landed` holds the runner by blocking
# the step AFTER it, and until that commit a last line had no step after it: the next scenario
# started the moment it returned and dropped the block with it. That is how the portal file
# still opened inside this crypt on 2026-09-28 with the walk out above already in place. Devkit
# now holds a run until its last step's wait is over, and the line stays because it is worth
# asserting: walking out is not entering, so coming back to the surface must leave the one pin
# there and add none.
pins 1 60
